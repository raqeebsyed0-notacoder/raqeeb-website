## D. AI project corrections — all eight
### AGENT FLEET — Running

- **Route:** `#/projects/ai/agent-fleet`
- **Corrected description:** Nine agents, one operating picture. Each seat owns a function, reports upward, and cannot act outside its role. The interesting problem was not building an agent; it was stopping nine of them from becoming nine separate systems.
- **Evidence at audit:** Nine seats live at audit time; one seat was in an error state on the day of the audit, so the status is Running with a caveat rather than Live. Coordinated through one issue board.
- **Stated limits:** Not an autonomous company: a human still holds every irreversible decision. No public throughput or cost-per-task metric exists, so none is claimed.
- **Links:** Interactive Fleet Topology; Fleet Request Journey Sequence
- **Measured:** og:image HTTP 200, 0 page errors, 0 console errors.

### SKILLS LIBRARY — Running

- **Route:** `#/projects/ai/skills-library`
- **Corrected description:** A prompt is a one-off. A skill is a procedure the agent can repeat on Tuesday without being reminded. This library is how the same standard survives across agents and sessions.
- **Evidence at audit:** 438 skill packages on the machine at audit time, plus 315 workflow skill packages from the orchestration layer.
- **Stated limits:** Quality varies by skill; a written procedure is only as good as the last time it was tested. No benchmark for skill effectiveness exists, so none is claimed.
- **Links:** Interactive Skills Path Dataflow
- **Measured:** og:image HTTP 200, 0 page errors, 0 console errors.

### ORIO OPERATIONS — Pilot

- **Route:** `#/projects/ai/orio-operations`
- **Corrected description:** A drilling services operator tracks equipment by rig, by well and by job cycle. When those three drift apart, the invoice and the field report disagree and someone spends a day reconciling. This console makes the drift visible before it becomes a dispute.
- **Evidence at audit:** Repository README (2026-10-20): operations and market-intelligence tracks, local SQLite per client, client-scoped API; two demo videos and interactive diagrams on disk.
- **Stated limits:** Demo-local by design: approving an action mutates demo state only; email, OneDrive and Telegram are blocked stubs that refuse to deliver. No production client data in the repository.
- **Links:** Interactive Operations Architecture; Market Intelligence Dataflow; two real demonstration videos
- **Measured:** og:image HTTP 200, 0 page errors, 0 console errors.

### LEADJIN — Pilot

- **Route:** `#/projects/ai/leadjin-portal`
- **Corrected description:** Saudi B2B lead generation has a trust problem: lists are cheap, verified contacts are not. LeadJin finds companies, finds the people inside them, verifies both, and refuses to send to anyone it cannot show a source for.
- **Evidence at audit:** Running locally at audit time: service port 3001 healthy, local model gemma4:e4b over Ollama, decision service port 8020; 6,701 company records of which 6,568 are licence-cleared.
- **Stated limits:** Pilot, not production. Registry lookup is optional and needs a known CR; Places returns no email or people, so contact harvesting is load-bearing. No Twenty CRM integration; pipeline state lives in the product’s own tables.
- **Links:** Interactive LeadJin Architecture
- **Measured:** og:image HTTP 200, 0 page errors, 0 console errors.

### APPROVAL INBOX — Running

- **Route:** `#/projects/ai/approval-inbox`
- **Corrected description:** An agent that can publish, send or spend should not be able to do it alone. This inbox puts the artefact in front of a human, in the place the human already works, and makes the decision the thing that unblocks the action.
- **Evidence at audit:** Repository README (main): single inbox, artefact previews, decision wakes the live session, opt-in injection flag that fails closed when unset; plugin installed and enabled on this machine.
- **Stated limits:** Live-session injection is opt-in and fails closed by default: without it a decision only records and creates a board card. No hash-chain audit trail exists, so none is claimed.
- **Links:** Interactive Architecture Diagram
- **Measured:** og:image HTTP 200, 0 page errors, 0 console errors.

### PAPERCLIP PLUGIN — Running

- **Evidence at audit:** Plugin installed and running; the board API answers with nine agents and a live issue set at audit time.
- **Stated limits:** One board implementation. The plugin follows that API’s shape; a different work system would need its own adapter.
- **Links:** Interactive Plugin Architecture
- **Measured:** og:image HTTP 200, 0 page errors, 0 console errors.
